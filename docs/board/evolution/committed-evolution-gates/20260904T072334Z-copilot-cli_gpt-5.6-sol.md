## Suggestion

- **Change:** Add one precondition to `docs/workflows/evolve.md`: the
  `loop: on` and evaluator baseline state used to authorize a cycle must
  already exist on the current default-branch commit before the experiment
  branch is created. An uncommitted `STOP` file must still halt the run.
- **Hypothesis:** This prevents an agent from passing its gate check against a
  dirty main worktree and then creating a variant from a parent commit with
  different owner-controlled gates. Removing that split state should improve
  first-try verification.
- **Score it should move:** S2, first-try verification pass rate, higher;
  tolerance 2%. S1, S3-S6, and constraints C1-C6 must not regress.
- **Signal:** `reflect.sh` reported main at `6bdadb7` with 53 uncommitted
  paths. The gate check saw `loop: on`, while `git diff` showed that the
  default-branch commit still contains `loop: off`.
- **Tier:** 1 under Accepted ADR-012. This is an operating-layer workflow
  change because the constitution lists no separate product class.

## Experiment card

- **File:** `docs/workflows/evolve.md`
- **One variable:** require committed positive owner gates before branch
  creation, without weakening the working-tree `STOP` check.
- **Fixtures:** Run F01-F14 three times each and replay the dirty-gate setup in
  an isolated clone; use only held-out fixture ids supplied by the maintainer.
- **Target:** S2 improves from the parent median; no other score worsens past
  its tolerance.
- **Fleet plan:** If parallel execution is useful, prepare isolated clones
  with `fleet.sh`, let workers produce result files only, validate them in the
  orchestrator, and clean every clone before reporting.
