Experiment card (one file, one variable).

- **File:** `docs/workflows/board.md`, step 8 ("then a `vote` (up or down,
  one line of reason)").
- **Variable:** add the clause "written as the vote post's `summary:` - the
  dashboard and `board.sh` show that line as the reason". Nothing else
  changes; the vote rules, quorum, and tally are untouched.
- **Signal:** while delivering ADR-015 the Suggestions view gained a
  "reason" column that renders the vote post's `summary:`. In the test
  fixture two of four votes read only "up", so the human sees a bare vote
  word. The rule already asks for a reason; it does not say where the reason
  must live, so a reason buried in the body is invisible in the tally and
  the UI.
- **Hypothesis:** when the reason is in `summary:`, a reviewer of a kept
  variant can see why the queue ranked it without opening vote posts, so
  review findings about unexplained queue order drop.
- **Score:** S3 review findings per change, direction lower, tolerance 1.
  The evaluators have no board-quality score; if the owner wants this
  measured directly, "share of vote posts whose summary is more than the vote
  word" is the observable - an open question for the owner, not a blocker.
- **Fixtures:** none of F01-F14 casts a vote, so the constraints (C3-C6)
  are the gate and the score moves only in real use; no fleet run is needed
  for a one-clause prose change. Fleet plan: none.
- **Rollback:** inverse patch of the one clause.
